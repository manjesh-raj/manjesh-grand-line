- **Hosts / SSH connection manager (Phase 1, `data/cockpit-ssh-manager-research/report.md` A2/A3, C1, D Phase 1).** `HostsController` (Termius-proportioned, 220-260pt, list, per-host SF-Symbol icon + Helm accent, quick-connect, add/edit/delete) is its own rail destination (see above); Add/Edit Host is a dedicated full-page window (`AppDelegate.presentHostEditor`), not a sheet on this narrow panel - `HostsController.onAddOrEdit` forwards the request up through `AppShellController` to the app delegate, which owns `HostEditorController` and the host store. Row zero is always a pinned, non-deletable "Firstmate" entry (anchor icon) whose connect action is `ConsoleController.openFirstmateHost()` - it has no backing `Host` record, so `HostsController`'s private `HostListRow` enum carries a `.pinned` case alongside `.header`/`.host`. A saved `Host` (`Host.swift`) is `Codable` and persisted by `HostStore` to `~/Library/Application Support/FirstmateCockpit/hosts.json` (override `FM_HOSTS_FILE`) - the native app's first on-disk persistence. **Secrets stay off disk:** `Host.password` is excluded from `CodingKeys` (session-only, memory); the only persisted credential is `keyID`, a reference into the Phase 2 key store below - never a path or key material. **Connect** for a saved host reaches its own dedicated page (see "Dedicated host pages" below) whose one ssh tab runs `/usr/bin/ssh` with the host's argv (the C1 drop-in) plus, when `keyID` is set, a `-i <path>` resolved fresh on every start (see below); the tab takes the host label + accent, and the tab chip's own Duplicate (`⌘D`) re-runs the same launch (re-resolving the key) for a deliberate second session. An ad-hoc quick-connect (`HostCatalog.parseQuickConnect`, no saved `Host` behind it) still opens as a plain tab in the shared Firstmate `ConsoleController` via `ConsoleController.openSSH(...)` directly, since there's no host id to pin a dedicated page to. The Hosts menu's Quick Connect routes through `AppShellController.revealHostsQuickConnect()`, which selects the Hosts destination before focusing it. The topbar Search control is unrelated to Hosts now - see "Find" below.
- **SSH keychain (Phase 2, `data/cockpit-ssh-manager-research/report.md` A1, C3, D Phase 2; Keychain model corrected in cockpit-native-fixes3).** `SSHKey.swift` is non-secret metadata only (label, type, derived public key, fingerprint, certificate), persisted by `SSHKeyStore` to `keys.json` (override `FM_KEYS_FILE`) exactly like `HostStore`. Private key bytes and passphrase live **only** in the macOS Keychain (`KeychainKeyStore.swift`: `SecItemAdd`/`SecItemCopyMatching`/`SecItemDelete`), stored with plain `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` (never iCloud-synced) - **not** a `SecAccessControl` ACL. That's a deliberate correction, not the original design: on a CLT-only, ad-hoc-signed build (`TeamIdentifier=not set`), `SecItemAdd` with *any* `kSecAttrAccessControl` fails `errSecMissingEntitlement`, confirmed with a standalone probe outside the app - see `KeychainKeyStore.swift`'s file header for the full writeup, including why a `keychain-access-groups` entitlement isn't a fix either (ad-hoc signing it gets the process killed outright, no provisioning profile). The Touch ID / passcode gate is therefore enforced in-app (`KeychainKeyStore.authenticate(context:)` calling `LAContext.evaluatePolicy` before the read), not by the OS ACL - revisit once the app has a real Team ID (Phase 4 packaging). Generation and PEM/OpenSSH import both shell out to `/usr/bin/ssh-keygen` (`SSHKeyGenerator.swift`) rather than reimplementing the OpenSSH key format or its passphrase KDF - `.ppk` files are detected and rejected with a conversion hint, not parsed. `SSHKeyStore.addNew(_:privateKeyData:passphrase:)` is the one path that writes a brand-new key (Keychain first, then metadata) - both the Keys screen and the host editor's inline "+ New Key…" popup entry (`HostEditorController.presentNewKeySheet`, still a sheet - now on the host editor's own window rather than the sidebar's) go through it, so a new key can be created without leaving the host form. At connect time `SSHKeyMaterializer.materialize` does the one Keychain read (the Touch ID prompt) and writes a private `0600` temp file for `ssh -i`; `ConsoleController.connectSSH`/`cleanupSSHKeyTempFile` own its lifecycle (fresh file per tab start/reconnect, deleted on close/exit/quit). The "SSH Keys" browser is the Hosts destination's **SSH Keys tab** (`HostsController.swift` + `KeyEditorController.swift`; Keys menu, `⌘⇧K`/`⌘⇧N`) - it was a separate 380x520 window until Phase 5 of the full-app UI audit folded it in, and its row Delete action (`SSHKeyStore.delete(id:)`) removes both the metadata and the Keychain items - see `KeychainKeyStore.delete(id:)`. A `swift build`/`swift run` binary has no stable code-signing identity, so Keychain access can prompt again (or rarely fail to re-read) across rebuilds; `native/build_native_app.sh` now codesigns the assembled `.app` with a fixed local identity to keep that identity stable across rebuilds (see the `build_native_app.sh` bullet below and its "Local signing setup" section in `native/README.md`) - not a full Phase 4 Developer ID/notarization setup, just a per-machine local dev cert.
- **Power features (Phase 3, `data/cockpit-ssh-manager-research/report.md` B1/B2/B4/B5, D Phase 3).** All additive `ssh` argv or extra `Host` fields, never new transport code. Jump hosts: `Host.jumpVia` (a saved host's label or a raw `user@bastion`) resolved and chained by `HostCatalog.proxyJumpChain` into `-J a,b,c`. Agent forwarding: `Host.agentForward` -> `-A` (the system agent's `SSH_AUTH_SOCK` is already inherited via `childEnvironmentDict`). Known-hosts prompts: no code needed - `connectSSH` never overrides `StrictHostKeyChecking` and nothing filters the ssh tab's PTY output, so they render like any other terminal output; verified by inspection, not a UI. Groups/tags: `Host.group`/`Host.tags` (present since Phase 1) now drive sidebar section headers and a tag-chip filter row in `HostsController`. Port forwarding: `Host.portForwards: [PortForwardRule]`, edited via `PortForwardingController` as a sheet on top of `HostEditorController` (a window since the nav-redesign task, not a sheet itself - see above), turned into `-L`/`-R`/`-D` flags. Snippets: `Snippet`/`SnippetStore` (mirrors `HostStore`), managed from the Hosts destination's **Snippets tab** (`HostsController.swift`; Snippets menu, `⌘⌥N`/`⌘⌥P`) - its own 360x480 window until Phase 5 of the full-app UI audit folded it in; Run sends text+Enter to the active tab via `TerminalView.send(txt:)`; a host's `startupSnippetID` fires the same way ~1.5s after ssh starts (best-effort, no "shell ready" signal exists to hook). Session logging was also part of this phase and has since been **removed outright** - see the next bullet.

## Hosts: a detail column instead of a dead middle

**`fm/grand-line-hosts-page-redesign` gave the Hosts destination the captain's reference layout - the list keeps its tabs, and a permanent right-hand stack (Workspace / Selected / Quick actions) takes the column the rows were spreading themselves across - and added the `.hosts` quick-access icon to the floating bar.** The reference is firstmate-side (`data/grand-line-hosts-page-redesign/reference-design.html`), like every prior redesign's; `HostsSidePanels.swift` and `SelfTests/HostsRedesignSelfTest.swift` are new.

- **All three tabs are real, which is the first thing this task had to establish rather than assume.** The brief's own instruction was to scope down if Hosts / SSH Keys / Snippets were not all real features - they are (`HostStore`, `SSHKeyStore`, `SnippetStore`, folded into one destination by Phase 5 of the full-app UI audit), so nothing was scoped out on that axis. What *was* scoped out is named below, each with its reason.
- **What the reference's own page content is, versus its chrome - the distinction PR #407 had to draw for Schedules, drawn again here.** Its `.app > .sidebar` (a "Terminal Hub" brand, a Tools section, an Appearance toggle) and its `.topbar` (a search pill, an icon row, an avatar) are a mockup drawing this app's own floating bar; only `.content-head`, `.tabs` and `.grid` are page content. So the tabs stayed as `HelmSegmentedTabs`, the `.content-head` was dropped (Daylight §6.4 - the drill header already carries the title, the live subtitle and the primary action, and Review/Docs/Health were each corrected for repeating it), and the `.grid` is the real change.
- **Two columns, not three.** Poneglyph's sidebar|list|inspector is the precedent for the *mechanism* (`CredentialVaultController.buildListContainer`), not for the shape: this page's nav is its three tabs, and a `HelmPageSidebar` duplicating them would be the same control twice, a row apart. The side stack is a **sibling of the three tab views**, not a child of each - its Workspace counts are page-wide and its detail panel simply re-fills from whichever list is showing, so one instance rather than three.
- **Window-floor discipline, and it is stricter here than Poneglyph's.** Both the side column's width (`HostsSideStack.width`, 320) and the content column's minimum (`HostsController.contentMinimumWidth`) sit at `HelmDaylightPriority.contentTie` (499), below `NSLayoutPriorityWindowSizeStayPut` - gotchas (13)/(14). Poneglyph pins its inspector width *required* and gets away with it; `HelmPageSidebar`'s header records the measurement that made 499 the rule, so this page took the rule rather than the precedent. Measured: content column exactly `page - 2*gutter - 320 - s4` at every width, and the page's own `fittingSize` stays 974 at 1016/1100/1400/1900.
- **The one AppKit finding: adding the side stack to the view tree has to precede the constraint block that names its anchors.** `loadView`'s first `NSLayoutConstraint.activate` block ties `tabs.trailing` to `sideStack.leading`, and activating a constraint between two views with no common ancestor throws - the same trap `fm/grandline-docs-no-window-fix` root-caused as a silent no-window launch.
- **Every panel is wired to something real, and what could not be is absent rather than padded.** The reference's fourth metric is a hardcoded "100% Keychain protected" (a claim, not a measurement) - it is **Live sessions**, counted through the page's own `liveSession` closure, i.e. the app's one `HostSessionRegistry`. Its status line's unconditional "Touch ID enabled" is `CredentialVaultKeyStore.biometryAvailable`, a real `LAContext.canEvaluatePolicy` probe, and says "no biometry on this Mac" when that is what it finds. Its filter bar offers three chips and this app can honestly answer one: **Online** is real, "All environments" is what the tag chips beside it already were, and **"Recently used" is scoped out** - no store here records when a host was last connected to, and adding a timestamp would be a new persisted field masquerading as a filter.
- **The quick-action grid carries four of the reference's six, and the literal list is the check.** `⌘K` / `⌘⌃N` / `⌘⇧N` / `⌘⌥N` are all really bound in `main.swift`; its `⌘↵ Connect selected` and `⌘⇧P Run snippet` are bound to nothing, so they are absent rather than drawn inert (the brief's own rule). Each button *performs* the action as well as naming it, so it is a control rather than a legend. **Connecting the selected row is offered as a real button in the Selected panel instead** - it runs the same closure the row's own Connect does - rather than by inventing a keyboard shortcut, which would be new functionality in a layout pass.
- **A truncated field is the field failing, not a whitespace complaint - Poneglyph's lesson, applied one page over.** In a 320pt panel a label-beside-value row leaves ~180pt for the value, which renders a real endpoint as `ec2-44-206-131-…-1.amazonaws.com`. A **code** field (endpoint, fingerprint, command) therefore gets the panel's whole width on its own line and wraps once; a short value (Environment, User, Credential) stays beside its label. The wrapping labels' `preferredMaxLayoutWidth` is re-read from the resolved layout in `layout()`, never guessed - an over-estimate is the dangerous direction (AppKit sizes the label one line tall and the second line draws outside its own bounds).
- **A live gotcha (11), found by measuring rather than by reading: `HostsDetailPanel.clear()` has to tear its rows down, not merely hide the view above them.** An ordinary hidden `NSView`'s constraints still participate fully in layout, so an emptied panel stayed as tall as whatever had last been selected - measured 317pt against the 168 it needs - and its height depended on a record nobody could see. `checkEmptyDetailTearsDownItsRows` pins it.
- **Selection plumbing is `HostsListSection.Item.recordKey` + `onSelectRecord`**, a caller-supplied `String` - the same "keyed by an id the list itself does not interpret" shape `HelmPageSidebar` uses, so that list still knows nothing about a `Host`. It is reported **before** the visible-row repaint's own `guard`, so what the detail panel shows never depends on whether a row happens to be on screen when the selection moves.
- **Part 2, the floating-bar shortcut: `.hosts` appends after `.console`, which satisfies the captain's "immediately next to the console icon" *and* this group's own append-never-slot-in convention at once** (console was already the trailing-most icon). `DaylightDestinationButton(destination: .hosts)` renders `HostsIcon.image` - the raster `RailDestination.drillHeaderArtwork` already carries - so the bar icon and the page cannot drift, and no new asset shipped. All six of the checklist edits in `DaylightBarController`'s own history were made, plus `DaylightModuleSelfTest.checkBarDestinationIcons`' **literal** expected list; the four that fail silently (target/action loop, key-view chain, theme sweep, debug list) are exactly why that list is a literal rather than derived.
- **Verified** by `swift build` (clean debug and release, zero warnings in this app's sources), the release binary confirmed to carry no `FM_RUN_*` strings or the new debug accessors, the full suite, and real off-screen renders (`cacheDisplay`) of the real mounted page - all three tabs, populated and empty - on `dusk`/`helm-light`/`daylight`, **without launching the app**, per the README's worktree rule. **Seven injected regressions each reproduced by name** (scripted file copies, never `git stash` - see this file's own warning about the shared stash stack): the side column made required, the panel no longer following the tab, the gotcha-(11) teardown reverted, the Online chip made inert, the panel's buttons unwired, the toolbar icon slotted in by topic, and a fabricated Workspace count.

## A hidden flexible sibling turns a `.required`-hugging control into a window-width ceiling

**`fm/grand-line-hosts-page-layout-regression-fix`: the captain opened Hosts and found no host list at all - the Workspace / Selected / Quick actions rail stretched across the whole page, with a narrow strip of colored swatches and tiny DEV/PROD labels where the list should be.** Read `buildHostsTab`'s `filterSpacer` comment before touching that row.

- **One bug, not the three the report describes.** The "collapsed sidebar of colored swatches" is not a sidebar - this page has none by design (#411's own decision: its nav is the tab strip, and a `HelmPageSidebar` would be the same control twice, a row apart). It is the *host list itself*, squeezed to 74pt, where all that survives of each row is its accent bar and its group header. Restore the column and both symptoms go with it.
- **Mechanism, and it generalises past this page: a `.required` content hugging priority is only safe while some *other* arranged subview can absorb the row's slack.** `filterRow` is `[onlineChip, tagsScroll]` at `.fill`, and `rebuildTagChips` sets `tagsScroll.isHidden = allTags.isEmpty`. An `NSStackView` drops a hidden arranged subview out of layout entirely (gotcha (11)'s own stack exemption), so with no tags the row is just the chip - whose hugging is `.required`. `filterRow.width == top.width`, `searchField.width == top.width` and `top` pinned to both edges of `hostsTabView` are all **required**, so that one chip's intrinsic width became a required *ceiling* on the entire content column. Measured on a real shell at the captain's own 1467pt window: content **74pt**, rail **1329pt**.
- **The fix is a permanently-present flexible spacer, collapsed by a real low-priority `width == 0`** - never a hugging priority, because a bare `NSView` has no intrinsic content size and `setContentHuggingPriority` on one is a documented no-op (gotcha (12); `fm/grandline-visual-polish-round2` paid for that lesson once already). Optional, so it yields when it is the only thing left to stretch and stays collapsed the rest of the time, leaving the tag strip exactly the slack it had before.
- **Why the fix is not a bigger priority change.** Lowering the chip's hugging would stretch a lone "Online" pill across the page; raising `contentMinimum` above 499 would make this page a window-width floor, which `AppShellBodyWidthSelfTest` sweeps every destination against. Measured after the fix: the two columns tile the page exactly at 800/900/1016/1100/1220/1467/1512/1900, and the page's own `fittingSize.width` stays 858 at every one of them.
- **Why the original pass shipped it green, and the transferable half: the fixture's *data shape* was the blind spot, not the rendering technique.** #411 verified with real off-screen renders and a passing suite, and both were honest - every fixture seeded `devHost()`/`prodHost()`, which carry `tags`, and a tagged host is precisely the case in which this collapse **cannot** occur, because the tag strip stays in layout and absorbs the slack. The captain's real `hosts.json` records an environment in `group` and carries **no tags at all** - the branch the code's own comment calls "the common case". Reproducing it took reading his real store (read-only, metadata only) and matching its shape; no amount of re-rendering the tagged fixture would have found it. **When a page has a branch its fixtures never take, seed the branch, not another window size.**
- **`checkTwoColumnLayoutSurvivesUntaggedHosts` is the guard, and it carries a vacuity check** (`HostsController.debugTagStripIsHidden`): the case only exercises the collapse while the strip is genuinely hidden, so a fixture that drifts back to tagged hosts fails loudly rather than passing while testing nothing. **Confirmed to catch the regression by scripted revert** (never `git stash` - see this file's own warning about the shared stash stack): it reports `content column is 77.5pt, want 1083.0pt` and `side column is 1325.5pt, want 320.0pt` while the pre-existing tagged-host case beside it still passes - the coverage gap, stated by the suite itself.
- **A live launch was attempted and is NOT what confirmed this.** The sanctioned probe app (`Scripts/build-probe-app.sh`, its own bundle id and scratch stores) launches behind the app lock screen, whose Automic Vault check timed out and retried indefinitely, so it never reached the page; it was quit immediately and the captain's own instance (confirmed still running, untouched) was never disturbed. The confirmation is instead a real `AppShellController` mounted in a real off-screen window at his exact window size, theme and data shape - rendered to PNG and looked at, in both registers.
- **A CI window-lane flake this task diagnosed in passing, so nobody re-diagnoses it: `CanvasListsControlsSelfTest`'s "D5 the row entrance is capped and plays once" tolerates only 1ms of wall clock.** `CABasicAnimation.beginTime` is stamped `CACurrentMediaTime() + delay`, so the `spread` it measures is `(real time between the two `HelmRowEntrance.play` calls) + cap`, not the cap alone - and the assertion is `spread > cap + 0.001`. Creating an `NSView` and adding it as a subview between those two calls therefore fails the case whenever a loaded runner takes more than a millisecond over it. Observed at **0.24113 against a 0.24 cap** (1.13ms elapsed) on one job while **the identical commit passed the same job on the other event** - flaky by definition, and unrelated to whatever branch happens to be running. Subtract the elapsed time, or widen the tolerance, if it is ever worth fixing.
- **Two read-only diagnostics worth reusing before guessing at a captain's environment**: `defaults read com.firstmate.cockpit.native` gives his real window frame (`NSWindow Frame GrandLineMainWindow`), theme and text scale, and `CFBundleVersion` on the installed bundle is a `git describe` string naming the exact commit he is running - which ruled out "he is on a stale build" in one command.

**`fm/grand-line-hosts-sidebar-restore`: the Hosts page has a left nav column again, and the decision that scoped it out is the captain's own to have overturned.** Read `HostsSidebar.swift`'s header and `HelmPageSidebar`'s `Surface`/`CountStyle`/`setFooter` doc comments before touching any of it.

- **What the "bug" actually was, reported honestly because the brief asked me to distinguish it from a cosmetic mismatch: the column was never built.** Not hidden, not collapsed to zero width, not behind a flag - `fm/grand-line-hosts-page-redesign` scoped one out by name ("Two columns, not three ... this page's nav is its three tabs, and a `HelmPageSidebar` duplicating them would be the same control twice, a row apart"). Confirmed by mounting the real page off-screen and walking its tree for a `HelmPageSidebar`: **0 instances**, with the render matching the captain's own "current UI" screenshot exactly. This is the same correction one page over that `fm/grand-line-schedules-sidebar-fullwidth-fix` already made after Schedules scoped its own column out for the same reason - **the second time a reference's `aside` has been read as mockup chrome when it was page content**, so check that reading before repeating it a third time.
- **The tab strip stays, and the two are wired as ONE mechanism.** The captain's target screenshot shows both, so the duplication the original decision worried about is answered by construction rather than by removing a control: the WORKSPACE rows are keyed by `HostsTab`'s own raw values, `select(tab:)` moves the sidebar's selection and a sidebar row calls `select(tab:)`, so a switch from either side lands in exactly one place. `HostsRedesignSelfTest.checkSidebarAndTabsAreOneMechanism` drives both directions.
- **`HelmPageSidebar` gained three things, all opt-in, so Poneglyph and Schedules render byte-identically**: `Surface.panel` (`HelmCard.applyCardSurface` plus a content inset - `.plain` keeps a zero inset, which is what leaves the two older pages' rows exactly where they were), `CountStyle.badge` (the reference's count pill - **built as a container's layer, never the label's own `backgroundColor`**, because with `drawsBackground` the *cell* paints a square fill over the layer and the corners would never round), and `setFooter(_:)`. **A page that sets a footer must pin the column's bottom with a required `==`, not the `<=` the other two use** - with no footer the column hugs its rows, so an inequality is right; with one, the footer is pinned to the column's own bottom edge and that edge only reaches the page if the page says so.
- **Every number in the footer is real, which is the whole risk in a mockup-led pass.** The reference draws a hardcoded 68% keychain bar and a decorative user row. The bar is instead **how much of the saved fleet authenticates with a key this app holds in the Keychain** (`Host.keyID`) - a real fraction, labelled in words underneath, and GL-14's rule holds: a fleet with no hosts reports no fraction rather than implying 0%. The name is `NSFullUserName()`, and the `...` opens **the same** `show(.settings)` and the same single logout confirmation the floating bar's avatar uses (`DaylightBarController.requestLogout()` exists for exactly that - one definition of the copy and the Return mapping, never a near-copy).
- **Both TOOLS rows open something that really exists, and that is the rule a nav row lives or dies by here.** Commands opens `.commandLibrary`; Activity opens the app's own captain's log via a new `AppShellController.openFleetLog()` + `FleetController.showLogTab()`. **Stated rather than implied: that feed is the *fleet's* activity (merges, tasks, sync, investigations and host-scoped incidents), not a per-host connection history - this app records none.** Everything else the reference's sidebar draws is absent rather than drawn inert, the same call `CredentialVaultSidebar` and `SchedulesController` each made about their own reference's extras.
- **Two things in the reference are deliberately absent, and the captain's own brief is what settles the first.** Its sidebar opens with a "Hosts / Secure workspace" logo block, which would repeat what the floating bar's drill cluster already says (§6.4's duplicate-title defect, corrected on Review, Docs and Health in turn) - and the captain's own enumeration of what this column must contain lists four things and is not one of them. Its full-bleed edge-to-edge column is a card here instead, which is what every other page-scoped column in this app is.
- **A three-column page legitimately *prefers* more width than a narrow window, and asserting the preference is wrong.** `HostsRedesignSelfTest`'s two-column case used to read `view.fittingSize.width <= width`; with the third column that is 1198.5 against a 1016pt window **while the three columns still tile 1016 exactly**, because every one of them is pinned at `HelmDaylightPriority.contentTie` (499), below `NSLayoutPriorityWindowSizeStayPut`. It asserts the tiling now - what the preference was ever a proxy for - and the *window* half is `AppShellBodyWidthSelfTest`. **Inverted, not deleted**, per this file's own convention for an assertion that has become a record of an overturned decision.
- **`AppShellBodyWidthSelfTest.bodyContainerTracksWindowWithSeededHosts` closes a real blind spot that predates this task**: `withScratchEnv` points every store at an empty scratch file, so the Hosts page in that suite's own all-destinations sweep renders **zero rows and no tag strip** - and the tag chip row is precisely what `fm/grand-line-hosts-page-layout-regression-fix` was about. The new case seeds tagged *and* untagged hosts before the shell is built and sweeps the window, including switching away and back.
- **Seven injected regressions, each reproducing by name** (scripted file copies, never `git stash` - see this file's own warning about the shared stash stack): the column's width made required (which took every destination down with it, 1100 -> 1220), the column built but never composed, the column built but hidden, the tab/column wiring broken, the reference's fabricated 0.68 bar, a TOOLS row made to latch, and the column never added to the tree - **that last one throws AppKit's "no common ancestor" `NSException` and takes the process down rather than failing by name**, which is the correct outcome for that shape and worth knowing before reading an empty suite log as a pass.
- **Verified** by `swift build` (clean debug and release, zero warnings in this app's sources), the release binary confirmed to carry no `FM_RUN_*` strings or any of the new debug accessors, the full `./Scripts/run-all-tests.sh` run (154 passed / 0 failed / 1 documented skip), and real off-screen renders of the real mounted page across `daylight`/`dusk`/`helm-light`/`gruvbox-light`/`catppuccin-mocha`, at 1016/1512/1900, and on all three tabs - **without launching the app**, per the README's worktree rule: the captain's real packaged instance was running throughout and shares this bundle identity.
