## Log Analyzer

**`.logAnalyzer` (`fm/grandline-log-analyzer-build`) is a daily-use rail destination pinned directly after `.review`** - an SRE troubleshooting workspace for output the captain has already captured (collect -> analyze -> identify -> correlate -> explain -> next steps -> investigate further -> create incident/runbook/ticket). Built against the captain's own full spec (`data/grandline-log-analyzer-build/original-spec.md`, sections 1-26) and a captain-approved interactive mockup (`data/grandline-log-analyzer-mockup/mockup.html` + `report.md`, which maps every element to a real `HelmTheme`/`HelmDesignSystem` token). Read those two before changing anything here.

- **The one structural rule: an analysis is two layers, kept apart on purpose** (`LogAnalyzerModels.swift`'s header has the full reasoning). The **local** layer (`LogLocalAnalysis`) is computed on this machine with no network at all - redaction, source detection, severity, error grouping, timeline - and is *always* present, so the page is genuinely useful with `claude` missing or offline. The **AI** layer (`LogAIAnalysis`) is what one `claude -p` call adds on top and can be absent. This split is what makes spec §9's Observed/Inferred/Unknown honest rather than decorative: only the local builder (which counted the lines) may emit `.observed`, and **`LogAnalyzerAI.parse` downgrades any link the model labels "observed" to `.inferred`** - enforced in code, not requested in the prompt. Confirmed to catch that regression, not just to pass.
- **Redaction (spec §14) has exactly one boundary, and it is proven by byte-level greps, not by reasoning about call order.** `LogAnalyzerController.addEvidence` is the only place raw text exists - it is a parameter and a local `let`, and only `LogRedactor.redact`'s output is stored on `LogEvidenceItem.text`. Nothing downstream (analysis, prompt, storage, copy, artifacts) has an unredacted copy to leak. `LogAnalyzerSelfTest` plants real credential-shaped values and then greps the literal bytes of (a) a fully-built AI prompt, (b) the investigate-further prompt, and (c) every file of a saved investigation - the only form of this check that survives someone reordering the pipeline. Verified to catch a real leak: disabling two detection rules made all three fail. A `LogRedaction` record carries a *kind* and a non-reversible *fingerprint*, never the value, so spec §14's "never automatically store detected secrets" is true by construction of that struct.
- **`LogRedactor`'s rule list is ordered and deliberately conservative.** Earlier rules win on overlapping matches (a `postgres://user:pw@host` connection string is matched before the generic `password=` rule). It matches named credential shapes, never entropy - an entropy scanner over kubectl output produces constant false positives on base64 blobs and hashes, which trains the captain to click straight past the review step. It is also idempotent: re-running over already-redacted text reports nothing new (the page re-detects on every render).
- **Terminal capture scope (spec §2), the captain's own resolved decision, is in `LogAnalyzerCapture.swift`** - read its header before touching it. Order: a manual terminal selection wins; otherwise the **most recently completed command's own block** (command line + output); otherwise a **bounded tail** (`fallbackTailLines`, 400). Never the full 10,000-line scrollback, never the viewport. Block boundaries come from the mechanism this app already has (`TerminalBlockTracker`'s OSC 133 markers), not a second one. **The real gap, investigated rather than assumed:** `ConsoleController.installShellIntegrationIfSupported` guards on `tab.blockTracker != nil`, and `addTab` only creates a tracker when `.ssh && blockViewOptIn && BlockViewFeature.isEnabled` - so the OSC 133 hook is active *only* on the one host that opted into Block View. Widening that hook to every SSH tab was considered and rejected (it injects keystrokes into a captain's live remote shell on hosts that never opted in, and Block View's own two prior production breaks are a warning against widening it casually); prompt-line heuristics were rejected as guessing. The bounded-tail fallback says exactly what it did and names Block View's per-host opt-in as the way to get exact capture.
- **`ConsoleController`'s "Analyze Logs" toolbar button** is a `HelmPageToolbar.labeledButton` sitting in the SRE Lead / Compose cluster (after Compose and, since `fm/grand-line-console-claude-usage-button` restored it, "Claude usage"), host pages only (`!isFirstmateConsole`, the same gating SRE Lead uses). It forwards `onAnalyzeLogs(capture, tabName)` and handles nothing itself; `AppShellController.connectHost` wires it, reassigning on every call so a renamed host shows its current label.
- **Spec §11 is resolved after the AI answers, not by asking the model to remember the library** (`LogAnalyzerCommandMatcher`). A suggested command is matched back onto a real `CommandLibraryStore` entry by comparing the executable + subcommand chain (`kubectl describe pod`) and a token-overlap floor, with a saved template's `{{token}}` placeholders acting as wildcards. A match **replaces** the generated text with the saved template and labels the row "From your library" - that is the actual point of §11. Matching is deliberately conservative: a false positive would be a lie about provenance.
- **Every artifact (spec §16-§19) is rendered locally from the investigation already on screen** (`LogAnalyzerArtifacts`) - no second model pass, so a section can never drift from what the captain just read, and the buttons work offline. Create Runbook writes into the real `DocsRunbookStore` and emits its command steps in the fenced shape `native/Scripts/sre_kubectl_mcp.py`'s `_extract_command_lines` reads, so a generated runbook is immediately runnable by SRE Lead - asserted in the self-test via `DocsRunbookMetadata.commandLines`, the Swift mirror of that parser. **Create Ticket produces text only**: there is no tracker client anywhere in this feature, so spec §19's "do not automatically create an external ticket" holds by construction.
- **Compare (spec §20/§21) reuses `DiffEngine` and the Tools page's own `DiffResultView`** - no second diff. The log-aware half on top of it is pattern-level (new / resolved / got-worse counted patterns), because §20's scenarios all differ on every raw line (timestamps, pod names) while the *errors* are what changed - exactly what `LogErrorExtractor.normalize` neutralises. An optional AI `.compare` pass appends prose for the differences a pattern diff cannot see; its absence costs nothing already shown.
- **Storage (spec §15/§23/§25) defaults to keeping nothing.** `LogAnalyzerStore.save` is the only writer, and `.doNotSave` still calls through so downgrading an already-saved investigation genuinely deletes it. Root resolution mirrors `CommandLibraryStore`'s exactly, **including honouring `FM_SHIFT_DIR` as well as its own `FM_LOG_ANALYZER_DIR`** - a store living inside `ShiftGitSync`'s `personal-tasks/` subtree that ignores `FM_SHIFT_DIR` will silently write into the captain's real synced clone from a self-test. One real bug the self-test caught: a counted pattern's `label` is a **real line from the log**, so `patterns` is written for a `.complete` save only - metadata-only means what spec §15 says it means.
- **Keyboard shortcuts (spec §24) were checked against `main.swift`, not assumed.** ⌘⇧L / ⌘⇧C / ⌘⇧T / ⌘⇧I were free. **⌘⇧R was not** - the Tab menu's "Rename Tab…" owned it at the time - so "Create RCA" is bound to **⌘⇧A** instead; taking ⌘⇧R would have silently broken a shipped shortcut. The Tab menu is gone from the menu bar now (`fm/grandline-console-tabs-restore-tabmenu-fix`, see "## Menu bar"), which frees ⇧⌘R again, but Create RCA stays on ⌘⇧A regardless - changing an already-shipped shortcut isn't that fix's to do. ⌘↵ is the Analyze button's own `keyEquivalent` (page-scoped, not a menu item) and Esc is `cancelOperation`, both deliberately responder-chain rather than global.
- **Layout notes worth keeping** (each one a real trap this page hit): the six tab bodies are arranged subviews of an **`NSStackView`**, because a hidden *arranged subview* is excluded from layout while an ordinary hidden `NSView` is not (gotcha (11)) - a plain container would have made every short tab as tall as the 620pt Analysis tab. The history rail is laid out with explicit constraints rather than a horizontal stack (a horizontal `NSStackView` has no "fill" alignment, so a scroll view inside one collapses to its content height) and **collapses to width 0 as well as hiding**, for the same gotcha (11) reason. The Analysis tab's raw-log pane is sized by a **priority-499** proportional width - no content constraint on this page may exceed `NSLayoutPriorityWindowSizeStayPut` (gotcha (13)).
- **Every list is a demand-driven `NSTableView`** (`LogAnalyzerViews.swift`), never an `NSStackView` of permanent rows - a raw-log pane routinely holds thousands of lines, and this codebase has hit that pathology four times. Expandable error-group rows are **flattened** into the same table (sample lines become their own rows), the way `ShiftProjectTaskListView` renders subtasks.
- **Spec §26 holds by construction**: this feature imports only `AppKit`/`Foundation`/`UniformTypeIdentifiers`/`Yaml`, adds no credential store, no API client and no infrastructure SDK, and only ever operates on text the captain provided. Its one external call is `claude -p` (`LogAnalyzerAI`, the fifth caller of the `Process` shape `SRELeadRunner.swift` established), always on already-redacted text.
- **Verified with `swift build` (zero warnings) plus `FM_RUN_LOG_ANALYZER_TESTS=1`**, which covers redaction (including the three byte-level greps), source detection, severity/grouping (43 near-identical lines collapsing to one counted pattern), timeline availability and its explicit unavailable message, correlation and the observed-downgrade enforcement, AI reply parsing (fenced/prose-wrapped/malformed), Command Library matching, all three artifact renderings, comparison, storage in all three modes, all ten analysis modes, and every branch of the terminal-capture rule - plus one end-to-end run through the real `Process`/parse path against a disposable fake `claude`. **Confirmed to catch real regressions, not just to pass**: disabling two redaction rules, removing the observed-downgrade, and making the capture send the whole buffer each reproduced specific named failures. `FM_RUN_CONTRAST_TESTS`, `FM_RUN_DIFF_ENGINE_TESTS`, `FM_RUN_DOCS_RUNBOOK_TESTS`, `FM_RUN_COMMAND_LIBRARY_TESTS`, `FM_RUN_BLOCK_VIEW_TESTS` and `FM_RUN_SHIFT_DATE_PARSER_TESTS` all still pass. **Not done, deliberately**: the page was never rendered live - this app shares one bundle identity across builds, so launching any copy can disturb the captain's own running instance (the convention the Review-page entries above already establish). The self-test binary exits before `NSApplication.shared` is ever touched, which is why running it is safe and launching the app is not.
- **`fm/grandline-log-analyzer-body-width-regression` fixed a real, shared-`bodyContainer`-corrupting bug this page's original PR shipped, found via `FM_RUN_APP_SHELL_BODY_WIDTH_TESTS=1`, not by launching the app.** The captain reported a blank/unpainted rectangle covering the right portion of the window on Console, Vault, *and* Review - unrelated destinations that share nothing except `AppShellController.bodyContainer`. Root cause: `buildCompareTab()` ties `comparePopupBefore`/`comparePopupAfter` to their own column at `.required` (`popup.widthAnchor.constraint(equalTo: beforeColumn/afterColumn.widthAnchor)`). That is a real, externally-added constraint, not something a stack's own `.gravityAreas` arrangement math would exempt for a hidden arranged subview (the mechanism gotcha (11) already documents) - so it stayed fully binding straight through the Compare tab (hidden until chosen), `tabContainer` (hidden until an analysis exists) and this destination's own root, all the way up to the *shared* `bodyContainer`, capping the whole window at whatever width the popup's populated menu items happened to need. `renderComparePickers()` always adds at least one item ("Paste below, or pick evidence…") plus one per captured evidence label - free-form text - so this could bite at varying widths depending on what a captain had captured. Confirmed live (via the self-test, never the app) that this is a second, structurally different way to reach the exact symptom `AppShellBodyWidthSelfTest.swift`'s header already documents for `fm/grandline-live-gap-rootcause-scout` - that one is a staleness in the width-*tie* mechanism itself; this one is a destination's own content capping the tie's *target* value. **Fixed the same way `buildAnalysisTab()`'s own 0.38-split constraint already does**: drop the two popup width ties to priority 499 (below `NSLayoutPriorityWindowSizeStayPut`, gotcha (13)) - the popup still fills its column whenever there's slack (the ordinary case), it just can no longer force the window bigger than it genuinely is. `compareBefore`/`compareAfter` (the `HelmTextView`s in the same row) did **not** need the same fix - confirmed by bisection, not assumed; their own compression resistance is `.defaultLow`; `NSPopUpButton`'s is `.required` by default, which is what let the popup's item-driven intrinsic width become a real floor. `AppShellBodyWidthSelfTest.swift` gained a fourth permanent case, `bodyContainerTracksWindowAcrossRealisticWidths`, sweeping 8 widths (1100-2000) specifically so a fix tuned to one dimension can't silently pass - confirmed live to catch the regression (reverting the priority to `.required` fails every swept width, not just one). **A second, unrelated, legitimate floor was found and deliberately left alone**: `LogAnalyzerController`'s Analysis tab (visible by default, unlike Compare) genuinely needs ~980pt of real content width for its raw/structured split to render without squishing - the new test's swept widths all sit above that floor on purpose; conflating that floor with this bug would have meant either weakening the Analysis tab's own real layout or writing a test that can't tell the two apart.
